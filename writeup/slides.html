Why this is not a CI script

The repo already runs two gates. One counts days. One counts files.

pr-time-limits.yml

inactive_cutoff=$(date -u -d '14 days ago' +%s)
age_cutoff=$(date -u -d '28 days ago' +%s)
  ...
  gh pr close "$number"
Fires on four of our ten. Every time by closing a working fix nobody read, telling its author nothing.

large-pr-review-gate.yml

LARGE_PR_FILE_THRESHOLD: "20"
// block large PRs unless approved
Fires on none of them. No pull request in the corpus touches twenty files.
The three questions that actually decide a pull request's fate — has someone already fixed this? does the body satisfy the written rules? is the proof really a proof? — are reading problems, not counting problems. That is the gap an agent fills and a workflow cannot.

The rule nobody wrote down — Bob found the hole

villa has six rules for LLM-assisted PRs and no rule that you must disclose using one. Without disclosure all six are unenforceable. Bob emitted llm-disclosure as source: inferred, carrying a rationale field instead of a quote — so a maintainer can see it was derived, and reject it.
27 rules. 25 quote a source line. 2 are marked inferred. Nothing is hard-coded in a checker.

What ships

A folder you drop into any repository. Then one prompt re-derives it.

The gate pack

.bob/custom_modes.yaml   three modes, minimal tool grants
.bob/rules-<slug>/       twelve rules files
contract.yml             27 rules, each with its source line
scripts/check_*.py       the script each mode drives
schemas/finding.json     one finding format
reports/                 ten PRs, scored, with SUMMARY.md
  • Nothing is villa-specific except contract.yml — and Bob wrote that by reading villa's own documents.
  • Point the same prompt at another repo's CONTRIBUTING.md and PR template, get that repo's contract.
  • Runs before you open the pull request, not after fourteen silent days. The three checkers take under a second on a cached PR; prior-art costs a handful of gh calls.
