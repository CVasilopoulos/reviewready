IBM Bob is not a tool we used to write this project. It is what the project ships as. The deliverable is Bob configuration: a compiled contract, three custom modes, twelve rules files, and the scripts those modes drive. Remove Bob and there is no product left.

**Four Bob sessions, 39.79 of an allocation of 40 Bobcoins.** We captured no screenshots during the event. Instead we exported the sessions from Bob's own local database, `~/.bob/db/bob.db`, which is the same store the IDE's consumption panel reads, using `scripts/export_bob_sessions.py` in the repository. Each file in `bob_sessions/` carries the task id, the exact prompt, the Bobcoin spend, the context-window breakdown and every tool call with its timestamp and target. Those are Bob's numbers, not ours.

**Session 01 — compiling the contract.** Given villa's `CONTRIBUTING.md`, its pull-request template, its `AGENTS.md` and two workflow files, Bob produced `contract.yml` in 94 logged edits between 19:44 and 19:51. This one is corroborated twice: by the session's own tool-call record and by Bob's `attribution_logs` table, its per-file edit log, which we exported as `bob_sessions/ATTRIBUTION.md`. Before compiling, Bob fanned out **four subagents in parallel** to survey villa's subprojects — three of them started within the same second — at a cost of 0.55 Bobcoins across the four.

**The rule nobody had written down.** villa has six rules governing LLM-assisted pull requests and no rule requiring you to disclose using one, which makes all six unenforceable. Bob spotted the gap and emitted `llm-disclosure` as an inferred rule carrying a rationale in place of a quote, so a maintainer can see it was derived and reject it.

**Sessions 02 and 03 — the checkers.** Bob wrote `scripts/check_prior_art.py`, `scripts/check_contract.py` and `scripts/check_evidence.py`, the three custom modes in `.bob/custom_modes.yaml`, and all twelve `.bob/rules-*/` files. It chose each mode's tool grant and explained the choice: read, execute and todo, with no write capability, because a review gate that can edit the thing it is reviewing is not a gate. Session 02 is titled "build the first checker" but produced two of them, which is why the next session is titled "the third".

**Bob debugging itself.** It caught its own mistakes repeatedly. It noticed that its first contract draft had buried a required rule inside another rule's check and rewrote it to stand alone. It wrote and ran a validation script over its own output to find duplicate identifiers and missing fields. While building the third checker it found a real bug in the second — a section parser treating headings inside code fences as boundaries — and wrote a corrected version rather than inheriting the fault. Its closing message in session 03 tabulates the three defects it had been warned about and how each was avoided.

**What Bob did not do**, stated because the distinction is what makes the rest checkable. Claude Code wrote the corpus runner, `reports/SUMMARY.md`, the demo page, the slides and the video, and made three bug fixes to the checkers after the first full corpus run — deriving tool names from the diff instead of a fixed list, accepting commit hashes written in parentheses, and searching either side of a before/after label. Those fixes came after the Bobcoins were exhausted. They are ordinary bug fixes, not new capability. Two planned checkers, interface-shape and subproject-router, do not exist for the same reason: the budget ran out at three.

`PROVENANCE.md` states all of this file by file, including a correction we published against ourselves: an earlier commit of this repository shipped six PNGs named as per-task Bob session summaries which were in fact copies of an unrelated screenshot. They were removed, and the database export replaces them.
